# Peripheral WebSocket API, version 2

This is version 2 of the [peripheral API](readme.md), made for the [Linux Peripherals Controller](https://github.com/OHF-Voice/linux-peripherals-controller) (LPC). Connect to:

```
ws://<lva-host>:6055/v2
```

Version 2 only carries the **status** of the assistant and a few **commands**. LVA creates no Home Assistant entities for a version 2 client: LEDs, buttons, child lock and sensors are the business of the peripheral, which talks to Home Assistant itself. LVA reports nothing about buttons to Home Assistant.

Messages are JSON objects. A message is an **event** when it reports something that is (a status, a measured value) and a **command** when it asks the receiver to do something. This does not depend on the direction:

- Event: `{"event": "<name>", "data": {...}}`. LVA sends the status of the assistant, the peripheral sends the state of its hardware mute.
- Command: `{"command": "<name>", "data": {...}}`. The peripheral tells LVA what to do, LVA asks the peripheral to switch its hardware mute.

The `data` field is omitted when there is no payload.

```
Peripheral                                LVA
    │──── WebSocket connect /v2 ───────────►│
    │◄─── event hello ──────────────────────│
    │◄─── events lva_status, timer_status, ─│   (the whole status, once)
    │     timer_remaining_*, timer_full_data_set,
    │     state, mute_status, volume_status,│
    │     media_player_status               │
    │                                       │
    │──── event hardware_mute_type ────────►│   (what the hardware can do)
    │──── event hardware_mute_status ──────►│   (read from the device)
    │◄─── event state {"state": "wake_word"}│   (user said the wake word)
    │◄─── event state {"state": "listening"}│
    │◄─── event state {"state": "speech_detected"}   (the user speaks)
    │──── command volume_up ───────────────►│   (user pressed a button)
```

## Events from LVA (LVA → peripheral)

| Event | Data | Description |
|-------|------|-------------|
| `hello` | `{"api_version": "v2", "supported_versions": ["v1", "v2"]}` | First message of every connection. |
| `lva_status` | `{"status": "connected" \| "disconnected"}` | Whether LVA is connected to Home Assistant. If LVA itself is not running, the WebSocket connection fails instead. |
| `state` | `{"state": "idle" \| "wake_word" \| "listening" \| "speech_detected" \| "thinking" \| "tts" \| "announce" \| "pipeline_error"}` | What the assistant is doing, see [States](#states). |
| `mute_status` | `{"status": "muted" \| "unmuted"}` | Microphone mute. |
| `volume_status` | `{"volume": int}` | Shared volume, 0 to 100. Shows 0 while the media player is muted. |
| `timer_status` | `{"status": "idle" \| "active" \| "paused" \| "ringing", "auto_stopped": bool}` | Status of the timer that is shown, see [Timers](#timers). `auto_stopped` is `true` in the message that reports that the last ringing timer stopped on its own after `--timer-max-ring-seconds`, otherwise `false`. `status` is already `idle` in that same message, no further message follows. The next `timer_status` message (for example a new timer) has `false` again. |
| `timer_remaining_time` | `{"seconds": int}` | Seconds left of the timer that is shown, 0 if there is none or one rings. A paused timer shows the time it had left when it was paused. Sent once a second while a timer counts down. |
| `timer_remaining_percentage` | `{"percentage": int}` | Time left of that timer in percent of its duration, 0 if there is none or one rings. |
| `timer_full_data_set` | `{"timers": [{"id": str, "name": str, "status": "active" \| "paused" \| "ringing", "total_seconds": int, "seconds_left": int, "percentage": int}]}` | All timers that ring, count down or are paused, in the order of [Timers](#timers): ringing ones first, then the ones that count down (the one that ends first first), then the paused ones (the one with the least time left first). Timers that ended and no longer ring are not listed. With it a device can show several timers, for example in different colors or as rotating signals. Sent when the set or one of the values changes, once a second while a timer counts down. A ringing timer has `seconds_left` and `percentage` 0. |
| `media_player_status` | `{"status": "idle" \| "playing" \| "silent" \| "pause"}` | Music player. `silent` is playing at a volume of 0 %. Music paused only for ducking counts as `playing`. During an announcement the value stays as it was. |

All events from LVA are status events: they are sent once after `hello` and then only when their value changes (`timer_status` when its `status` changes). If several change at once, `lva_status` and the timer events come first, then `state`, `mute_status`, `volume_status` and `media_player_status`. A timer that a wake word or a button ended is therefore reported before the new state.

### States

- `idle`: nothing happens.
- `wake_word`: a wake word was detected, the wake sound plays.
- `listening`: LVA listens to the user. After a button start the start-listening sound plays first, so the state stays `idle` until listening begins.
- `speech_detected`: Home Assistant hears speech (voice activity), from its start until the request is being processed. Without speech the state stays `listening`.
- `thinking`: Home Assistant processes the request.
- `tts`: spoken reply. A follow-up question goes `tts`, then `listening` again.
- `announce`: voice or media player announcement.
- `pipeline_error`: the voice pipeline failed. It is followed by `idle` immediately, without any delay: the next message, sent in the same moment. It is a short signal, for example for a brief error animation.

Muted and a ringing timer do not change the state.

### Timers

Version 2 has no timer list of its own, it reports the timer list of LVA (see [Timers](../behavior.md#timers)), also while Home Assistant is not connected. `timer_status`, `timer_remaining_time` and `timer_remaining_percentage` only show one timer: a ringing one first (the one that rings longest), else the one that counts down and ends first, else the paused one with the least time left. `timer_status` is `ringing` while one rings, `active` while one counts down, `paused` if the only timers left are paused, else `idle`. A timer that someone stops (button, stop word, wake word) ends without `auto_stopped`.

A ringing timer that nobody stops ends on its own `--timer-max-ring-seconds` after it started ringing. When the last ringing timer ends this way, `timer_status` changes with `auto_stopped: true`. The full list of timers is in `timer_full_data_set`.

## Events from the peripheral (peripheral → LVA)

Only if the hardware supports it: a device without a hardware mute sends none of these.

| Event | Data | Description |
|-------|------|-------------|
| `hardware_mute_type` | `{"type": "none" \| "changeable" \| "read_only"}` | What kind of hardware mute the device has: none, one that software can switch (`changeable`), or one that can only be read (`read_only`). |
| `hardware_mute_status` | `{"status": "muted" \| "unmuted"}` | The hardware mute of the microphone. Not sent for the type `none`. |

## Commands from the peripheral (peripheral → LVA)

| Command | Data | Description |
|---------|------|-------------|
| `listening_start` | none | Start listening without a wake word, like the start-listening button. Ignored while muted, with no wake word active, or while a pipeline runs. Also silences all ringing timers. Without Home Assistant it only silences the ringing timers. |
| `listening_stop` | none | Stop the reply, the announcement and the pipeline, like the stop word. Ignored while a timer rings, and never touches the music. |
| `muted_on` / `muted_off` | none | Mute or unmute the microphone like the Mute switch, with its sound. Ignored if already in that state. Works also while `--enable-remote-unmute 0` (only Home Assistant is kept from it, see [behavior.md](../behavior.md#mute)). Home Assistant is told through the Mute entity, which is a read-only sensor then. |
| `volume_up` / `volume_down` | none | Change the volume by one step (`--peripheral-volume-step`) and play the volume step sound (`sounds/volume_step.wav`). At the limit (`volume_up` at 100 %, `volume_down` at 0 %) it changes nothing and plays the volume limit sound (`sounds/volume_limit.wav`) instead. Neither sound has an option. |
| `volume_set` | `{"volume": int}` | Set the volume, 0 to 100. Values outside are clamped, no sound. |
| `volume_silent` | none | Set the volume to 0, no sound. Use it as a mute for the output. `volume_up` brings the sound back, `volume_status` and `media_player_status` (`silent`) follow. |
| `timer_stop` | none | Stop all ringing timers, also without Home Assistant. Ignored if none rings. |
| `button_pressed` | `{"press": "single" \| "double" \| "triple" \| "long"}` | A button was pressed. LVA plays the matching sound for `double`, `triple` and `long` (`--button-double-press-sound`, `--button-triple-press-sound`, `--button-long-press-sound`). `single` plays nothing. |

An unknown command or invalid data is ignored and logged as a warning. The connection stays open. Commands change the assistant like the same action from Home Assistant, which sees the new volume, mute and media state.

## Commands from LVA (LVA → peripheral)

Only if the hardware supports it: LVA sends these only when the type is `changeable`.

| Command | Data | Description |
|---------|------|-------------|
| `hardware_muted_on` / `hardware_muted_off` | none | Mute or unmute the hardware of the microphone. LVA does not send them yet, see [todo.md](../../todo.md). |

## Hardware mute

Some hardware can mute its microphone itself, and sometimes software can switch that. The device is always the authority: the peripheral reads the state from the device and reports it after every (re)connect, and LVA never pushes its own mute onto the hardware when a peripheral connects. The messages are listed in [Events from the peripheral](#events-from-the-peripheral-peripheral--lva) and [Commands from LVA](#commands-from-lva-lva--peripheral).

LVA keeps type and status **for its own processing only**: it does not change its own mute (the Mute switch, `mute_status`), does not pass them on to other clients and creates no Home Assistant entity, because the peripheral shows the hardware mute in Home Assistant itself. The sync of the mute of LVA with the hardware mute is planned.

## Python quick-start

```python
import asyncio
import json
import websockets

async def main():
    async with websockets.connect("ws://localhost:6055/v2") as ws:
        async for raw in ws:
            msg = json.loads(raw)
            print(msg.get("event") or msg.get("command"), msg.get("data", {}))
            if msg.get("event") == "state" and msg["data"]["state"] == "idle":
                await ws.send(json.dumps({"command": "volume_up"}))

asyncio.run(main())
```
