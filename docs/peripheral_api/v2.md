# Peripheral WebSocket API, version 2

This is version 2 of the [peripheral API](readme.md), made for the [Linux Peripherals Controller](https://github.com/OHF-Voice/linux-peripherals-controller) (LPC). Connect to:

```
ws://<lva-host>:6055/v2
```

Version 2 only carries the **status** of the assistant and a few **commands**. LVA creates no Home Assistant entities for a version 2 client: LEDs, buttons, child lock and sensors are the business of the peripheral, which talks to Home Assistant itself. What the status means for the user is described in [behavior.md](../behavior_peripheral_api.md).

Messages are JSON objects. Events from LVA: `{"event": "<name>", "data": {...}}`. Commands to LVA: `{"command": "<name>", "data": {...}}`. The `data` field is omitted when there is no payload.

```
Peripheral                                LVA
    │──── WebSocket connect /v2 ───────────►│
    │◄─── hello ────────────────────────────│
    │◄─── lva_status, state, mute_status, ──│   (the whole status, once)
    │     volume_status, timer_status,      │
    │     timer_remaining_*, media_player_status
    │                                       │
    │◄─── state {"state": "wake_word"} ─────│   (user said the wake word)
    │◄─── state {"state": "listening"} ─────│
    │◄─── state {"state": "speech_detected"}│   (the user speaks)
    │──── command: volume_up ──────────────►│   (user pressed a button)
```

## Events (LVA → peripheral)

| Event | Data | Description |
|-------|------|-------------|
| `hello` | `{"api_version": "v2", "supported_versions": ["v1", "v2"]}` | First message of every connection. |
| `lva_status` | `{"status": "connected" \| "disconnected"}` | Whether LVA is connected to Home Assistant. If LVA itself is not running, the WebSocket connection fails instead. |
| `state` | `{"state": "idle" \| "wake_word" \| "listening" \| "speech_detected" \| "thinking" \| "tts" \| "announce"}` | What the assistant is doing. `speech_detected`: Home Assistant detected speech (voice activity). It follows `listening` and lasts until `thinking`. |
| `mute_status` | `{"muted": bool}` | Microphone mute. |
| `volume_status` | `{"volume": int}` | Shared volume, 0 to 100. |
| `timer_status` | `{"status": "idle" \| "active" \| "ringing"}` | Timers. |
| `timer_remaining_time` | `{"seconds": int}` | Seconds left of the timer that ends first, 0 if none. Sent once a second while a timer counts down. |
| `timer_remaining_percentage` | `{"percentage": int}` | Time left of that timer in percent of its duration, 0 if none. |
| `media_player_status` | `{"status": "idle" \| "playing" \| "silent" \| "pause"}` | Music player. `silent` is playing at a volume of 0 %. |
| `pipeline_error` | `{"reason": str}` | The voice pipeline failed. Followed by `state` `idle` if the state was not `idle` yet. |
| `hardware_mute_on` / `hardware_mute_off` | none | Mute or unmute the hardware of the microphone. Only sent if the type is `changeable`. LVA does not send them yet, see [todo.md](../../todo.md). |
| `timer_auto_stopped` | `{"seconds": int}` | The ringing timer stopped on its own after `--timer-max-ring-seconds`, `seconds` is how long it rang. Followed by `timer_status` `idle`. |

The events `hello`, `pipeline_error`, `timer_auto_stopped`, `hardware_mute_on` and `hardware_mute_off` are single signals. The others are status events: they are sent once after `hello` and then only when their value changes. If several change at once, `lva_status` and the timer events come first, then `state`, `mute_status`, `volume_status` and `media_player_status`. A timer that a wake word or a button ended is therefore reported before the new state.

## Commands (peripheral → LVA)

| Command | Data | Description |
|---------|------|-------------|
| `start_listening` | none | Start listening without a wake word. |
| `stop` | none | Stop the reply, the announcement and the pipeline. Ignored while a timer rings. |
| `mute_on` / `mute_off` | none | Mute or unmute the microphone. Works also while `--enable-remote-unmute 0`. |
| `volume_up` / `volume_down` | none | Change the volume by one step (`--peripheral-volume-step`) and play a short step sound. At the limit (`volume_up` at 100 %, `volume_down` at 0 %) it changes nothing and plays the limit sound instead. |
| `volume_set` | `{"volume": int}` | Set the volume, 0 to 100. |
| `timer_stop` | none | Stop a ringing timer. |
| `hardware_mute_status` | `{"status": "muted" \| "unmuted"}` | Report the hardware mute of the microphone. The device is the authority: report the state read from the device after every (re)connect. LVA keeps it for its own processing, it does not change its own mute and passes nothing on. |
| `hardware_mute_type` | `{"type": "none" \| "changeable" \| "read_only"}` | Report what kind of hardware mute the device has: none, one that software can switch, or one that can only be read. |
| `button_pressed` | `{"press": "single" \| "double" \| "triple" \| "long"}` | A button was pressed. LVA plays the matching sound (none for `single`). |

An unknown command or invalid data is ignored and logged as a warning. The connection stays open.

## Python quick-start

```python
import asyncio
import json
import websockets

async def main():
    async with websockets.connect("ws://localhost:6055/v2") as ws:
        async for raw in ws:
            msg = json.loads(raw)
            print(msg["event"], msg.get("data", {}))
            if msg["event"] == "state" and msg["data"]["state"] == "idle":
                await ws.send(json.dumps({"command": "volume_up"}))

asyncio.run(main())
```
